# Utility-model input sets — target-shaped score tables

**Not canon.** Records the `Inputs`-sheet values that make the *utility-adjusted
unrounded score* tables in `tools/scoring models/archmage_scoring_m15_utility_model_v4_formula_corrected.xlsx`
round to the target shape, one set per deck.

Machine form (inputs + full unrounded/rounded scores, both decks):
`tools/scoring models/recorded_target_tables.json`, regenerated by
`tools/scoring models/record_target_tables.py` (which drives the kept
`_m2.py` model). The tables below are the human-readable snapshot.

## Target shape (both decks, when the unrounded scores are rounded to integers)

1. **C3 = 0** (3-card Conjuration reads as the floor).
2. **Every other score > 0.**
3. **Each spell column strictly increasing** with size (Conjuration, Transfiguration, Perfect Transmutation, and the short Enchantment column).
4. **PT15 = 100** (the model forces PT15 = Conj15, so the ceiling is the Conj15 = PT15 identity).
5. **PT ≥ Transfiguration at every size.**

## Important: the inputs are shared, so this is one config per deck

`alpha`, `lambda`, `scale`, and the TF role incentive are **global** `Inputs`
cells — only `Deck 1 energies` (B5 = 4) and `Deck 2 energies` (B6 = 5) differ per
deck. The workbook therefore holds **one deck's configuration at a time**; the two
sets below are alternatives, not simultaneous. As recorded, the workbook is loaded
with the **Deck 1** set.

Only four cells change from the workbook defaults; every other `Inputs` value stays
at default (mu B24 = 1, score-scale aside; horizon B26 = 2, card-draw B27 = 1,
clock-penalty B28 = 0.25, array B29 = 0.6, friction B30 = 0.8, PT-util-mult B31 = 0.65,
capacity B32 = 0.75, gains B33/B34/B35 = 1/3/5, ranks B4 = 15, opportunity B9 = 15).

## How these were derived / verified

The four utility params (alpha, lambda, scale, TF-role) were the only levers; the
low-end constraint (C3 → 0 while the column stays strictly increasing) is what forces
alpha off its default — the utility discount's size-6 doubling flattens the low end
otherwise. Values were found by searching the input space and maximising the minimum
distance of every cell from a rounding boundary.

Verification was done against a Python reimplementation of the full formula chain
(`Fixed_Opportunity → Marginal → Combined_Fixed → Utility_Model`), confirmed to
reproduce the workbook's own computed values to < 1e-9 for **both** decks before the
input changes. No live Excel/LibreOffice recalculation was available in-session; the
workbook is saved with full-recalc-on-load so Excel reproduces these tables on open.

To switch the workbook between decks, set B7/B23/B25/B36 to the row above for the deck
you want. To revert to stock model behaviour, set them back to 0.8 / 0.5 / 2 / 1.5.

## Shared table — one table for both decks (A = 4E, B = 5E)

Goal: a single printed score table usable by both decks. A **single shared input
set cannot do it** — Deck A's targets pin the utility inputs to a razor-thin ridge
(alpha ≈ 0.816, lambda ≈ 0.27), and at those exact inputs Deck B's 3-card Conjuration
rounds to 1 (not 0) and its PT15 blows past 100 (≈112). So the shared table is built by holding **Deck A at its optimal table** and
**re-tuning Deck B with its ceiling relaxed** (PT15 no longer forced to 100, so its
scale is free) to hug Deck A across sizes 3–9, then an **A-favoured blend**:

- **Re-tuned Deck B** (shared-table use only; its standalone table is the Deck 2 set
  above): alpha **0.79**, lambda **0.55**, scale **3.0**, TF-role **0.15**. Freeing the
  scale lets B's low-mid curve sit almost on top of A's — the A↔B rounded gap over 3–9
  drops to Conj `0,0,0,0,1,2,1` / TF all `0` / PT off by 1 only at size 4 (was Conj
  `0,0,0,1,3,3,3` and TF up to 3). Re-tuned B's PT15 lands ≈ 96 (relaxed).
- **Weight on Deck A** = 0.65 for sizes 3–9 (Deck A is the more common deck — 4E =
  2–4 players — so the shared value leans to A even where they agree), ramping to 1.0 at
  size 15. **PT15 = 100 comes from Deck A.**

The shared table satisfies every target: C3 = 0, all other scores > 0, each column
strictly increasing, PT15 = 100, PT ≥ TF at every size. Per-deck error at the common
7–8 range is now at most ±1 (size 7 → A +1 / B 0; size 8 → A +1 / B −1), down from ±2.

**Enchantment is decoupled** from the Conj/TF/PT re-tune. The re-tune's high lambda
(0.55, needed to match Conjuration) over-discounts capacity and flattened the top — it
gave 4, 9, 11 (jump +5 then only +2). Enchantment instead blends Deck A with Deck B
**standalone** (lambda 0.28), giving **4, 10, 16** (jumps +6, +6). Size 5 applies to
Deck B only (a 4-energy deck can't build it). Enchantment magnitude stays the least
settled column — its final shape is tied to the open UC/capacity reprice
(`enchantment-capacity.md`).

Machine form: `shared_table` block in `recorded_target_tables.json` (holds the re-tuned
B inputs, standalone-B Enchantment source, and weights). Build/inspect via `_matchB.py`
(re-tune B + A-favoured blend); `_shared_table.py` shows the shared-input-set
infeasibility; `_ench.py` diagnoses the Enchantment column. Weighting/crossover are
judgment calls — adjust `blend_weight` or the re-tuned inputs (`RETUNED_B`) in
`record_target_tables.py` to reshape.

### Mid-range (size 7–8) divergence — flagged, then addressed

Sam flagged (2026-07-08) that size 7–8 is probably the most common end-of-game spell
size, so a shared value over-rewarded in one deck and under-rewarded in the other could
make scoring *feel* different between decks. The **earlier midpoint blend** (of the two
standalone optimal tables) left Conjuration errors up to ±2 there:

| size | midpoint shared Conj | Deck A fair (err) | Deck B fair (err) |
|---:|---:|---:|---:|
| 7 | 7 | 6 (+1) | 9 (−2) |
| 8 | 14 | 12 (+2) | 15 (−1) |

**Addressed** (see the shared-table section above): relaxing Deck B's ceiling and
re-tuning it to hug A, plus a mild A-favoured weight, cut the size 7–8 per-deck error to
≤ ±1. The residual is a genuine difficulty difference (a 7–8 Conjuration is harder in the
5E deck), so ±1 is about the floor without distorting one deck further. Confirm against
live scoring feel at both player counts before committing.
